# 7.4 — Turn Unix fd passing on

**Workstream:** 7 — Unix FD passing
**Context:** [dbus-unix-fd-passing.md](../dbus-unix-fd-passing.md) §Recommended layer boundary
**Requires:** [7.1], [7.2], [7.3]
**State:** draft

## What

`dbus_transport_unix:support_unix_fd/0` returns `false` with a comment pointing at
[dbus-unix-fd-passing.md](../dbus-unix-fd-passing.md). It is the switch: `dbus_auth_client_mech`
sends `NEGOTIATE_UNIX_FD` only when it is true, so until the three issues above are in,
returning `true` would agree to a protocol the code cannot speak. Flipping it is this issue,
and so is the end-to-end test that says it was safe to flip.

Keeping the flip separate is also what makes a bisect useful: everything before it is inert
by construction, and the first commit that can change what a peer sees is the one-line one.

The test that matters is the one that crosses the whole stack against a real `dbus-daemon`
rather than a `socketpair` — a descriptor is only meaningful if it still names the same open
file after the round trip. `dbus-daemon` refuses `NEGOTIATE_UNIX_FD` on TCP, so the same
suite run over `tcp:` is the negative case, and it should show a connection that works
normally with `agree_unix_fd = false`.

## Checklist

- [ ] `dbus_transport_unix:support_unix_fd/0 -> true`; drop the "Not implemented yet" comment
      and restore the moduledoc paragraph on fd passing, minus the `{otp, meta}` store
      [7.2](7_2.md) removed.
- [ ] A CT case that connects to the session bus, sends a message carrying a descriptor to a
      helper that echoes it back, and verifies the descriptor names the same file — compare
      `st_dev`/`st_ino` through the helper, not the descriptor number, which is expected to
      differ.
- [ ] A CT case over `tcp:` asserting `NEGOTIATE_UNIX_FD` is never sent and the connection
      authenticates normally.
- [ ] `README.md`: state that Unix fd passing is supported on `unix:` transports, that the
      value of an `h` is an index into `#dbus_message.fds`, and that received descriptors
      belong to the owner process.
- [ ] Remove [dbus-unix-fd-passing.md](../dbus-unix-fd-passing.md) §Conclusion's work list,
      or mark it done — the doc becomes the description of what the code does.

## Acceptance

- [ ] `rebar3 ct` passes with a session bus available, and skips rather than fails without one.
- [ ] A trace of the auth conversation on `unix:` shows `NEGOTIATE_UNIX_FD` and
      `AGREE_UNIX_FD`; on `tcp:` it shows neither.
- [ ] The echoed descriptor's `st_dev`/`st_ino` match the original's; its number does not.
- [ ] `lsof -p <beam>` after the suite shows no descriptors left from it.
- [ ] Every module in the workstream compiles with no new dialyzer warnings.
