# 7.3 — Framing descriptors, and who owns them afterwards

**Workstream:** 7 — Unix FD passing
**Context:** [dbus-unix-fd-passing.md](../dbus-unix-fd-passing.md) §Resource ownership
**Requires:** [7.1], [7.2]
**State:** draft

## What

`m:dbus_connection` accumulates bytes in `#state.acc` because a Unix socket is a byte stream
and a `recv` is not a message. Descriptors need the same treatment and get a second queue
beside it: `recv/2` now returns `{ok, Data, Fds}`, the reader forwards both, and
`unmarshal_data/2` takes `UNIX_FDS` of them off the front as each message is framed.

A queue is sufficient, and it is worth saying why rather than hoping: the kernel delivers
ancillary data no later than the last byte of the segment it was attached to. Descriptors
therefore arrive at or before the end of the message that declares them, never after it and
never reordered against it — so the first *n* in the queue always belong to the first message
that asks for descriptors, even when the peer packed several messages into one `sendmsg`.
When a message is byte-complete and the queue is short, [7.1](7_1.md)'s `unmarshal_data/2`
answers `more`: the rest is in flight, and the next `recv` completes it.

**Negotiation is enforced here**, because this is the layer that knows the answer —
`#state.agree_unix_fd`, set from `AGREE_UNIX_FD` in `handle_begin/2`. Sending a message with
descriptors without it is `{error, unix_fd_not_negotiated}`; receiving one is a protocol
error and stops the connection. The transport ([7.2](7_2.md)) knows only whether the socket
*can* carry them.

**Ownership has to be stated, because OTP cannot close a descriptor.** `socket:open/2`
adopts one and `socket:close/1` then closes it, but only for a socket — and what D-Bus
usually carries is a file, a pipe or a `memfd`, for which `file` and `prim_file` offer
nothing. So the library cannot promise to close what it receives, and any design that assumes
it can is wrong. The contract that follows: descriptors delivered to the owner in
`#dbus_message.fds` are the owner's, to consume with `socket:open/2`, a port program or a
NIF. The paths where nobody takes delivery — a message that fails to parse, descriptors that
arrive unnegotiated, a queue left over when the connection dies — are the library's, and it
handles them by calling an application-supplied closer if one is configured and otherwise
logging what it is about to leak. A leak with a count and a reason attached is a
diagnosable bug; a silent one is not.

## Checklist

- [ ] `#state.fds = []`: append what `recv/2` returned, pass it to `unmarshal_data/2`, keep
      what comes back.
- [ ] `reader_loop/2` forwards `{data, Data, Fds, self()}`.
- [ ] `handle_call({send, Message}, …)`: refuse `#dbus_message.fds =/= []` when
      `agree_unix_fd = false`, otherwise pass them to `dbus_transport:send/3`.
- [ ] Received descriptors while `agree_unix_fd = false`: discard them and stop with
      `{unexpected_fds, N}`.
- [ ] `{dbus, Msg}` to the owner carries the descriptors on the record; document in the
      moduledoc that they transfer with it and the library will not close them.
- [ ] A `fd_closer` application environment key — `{Module, Function}` taking one descriptor
      — called on the discard paths: unmarshal failure, unnegotiated descriptors, and
      `terminate/2` with a non-empty queue.
- [ ] Log at warning what is discarded when no closer is configured: how many, and why.

## Acceptance

- [ ] `rebar3 ct` passes.
- [ ] Against a real bus over `unix:path=`, a method call carrying a descriptor is sent and
      its reply's descriptors arrive on `#dbus_message.fds`.
- [ ] A message whose bytes arrive split across two `recv`s, with the descriptors on the
      first, is framed once and carries them.
- [ ] Two messages in one `sendmsg`, the first with no descriptors and the second with two,
      give the two to the second message.
- [ ] Sending a message with descriptors on a connection that negotiated none is
      `{error, unix_fd_not_negotiated}` and nothing reaches the socket.
- [ ] A configured `fd_closer` is called exactly once per descriptor when the connection
      terminates with a non-empty queue, and `lsof` on the beam shows them gone.
- [ ] With no closer configured the same case logs a warning naming the count, and the
      connection still terminates cleanly.
